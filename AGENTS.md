## 6. n8n workflow facts
Lanes (all in one workflow, node names de-duplicated with suffix like `[3 Meetings]`):
1. **Lead engine**: webhook `fenebris-scraper-batch` only. The launch toggle picks the source. **AI Ark** `POST /v1/people` then `POST /v1/people/export/single` (BounceBan; about 1.5 credits per person). **Apify** actor `b2bsearch/b2b-leads-finder` (`APIFY_ACTOR_ID`, token `APIFY_TOKEN`): same titles, places, industry, company size, work-vs-any email, and max-per-company; phones stay off; about $1.50 / 1,000 leads with a live current-company email. Then one ICP filter → dedupe → Abstract only if the lead was not already verified → site/PageSpeed → GPT qualify + 4 emails, gate ≥ $1,000 → **Smartlead**. A known revenue outside $100k–$10M is dropped; a missing revenue is kept (stored as 0 and shown as unknown). If `ctx.places` is non-empty, the US/UK/EU/UAE country drop is skipped. Add-lead URL is `campaigns/{{ ctx.campaignId }}/leads`. Allowlist is the five ids below; missing or invalid falls back to `4238486`. That URL is live in the published workflow (SQL patch 2026-10-28, then a container restart).
2. **Reply brain**: webhook `fenebris-outreach-events` accepts the dashboard header, body `secret_key`, or query `secret_key` (the query form was patched onto the published If node). Events EMAIL_SENT/OPEN/LINK_CLICK/REPLY/BOUNCE → classify → Cal.com open slots → GPT draft → Smartlead `reply-email-thread` only when the send policy passes. Not interested is added to the Smartlead block list. Pause/resume looks the lead up by email, then pause/resume in the lead's own campaign (`body.campaignId` or Smartlead `lead_campaign_data[0].campaign_id`). Pause, resume, reply-thread, and the meeting-lane pause now use the lead's campaign id (source + imported 2026-10-28; the old `4224571` is gone from the imported workflow).
3. **Meeting sync**: `fenebris-cal-booking?token=…` (BOOKING_CREATED/RESCHEDULED/CANCELLED) → Postgres lookup → Google Calendar find/create/update/delete. Source title is `[BrandFly Discovery] {Company} ({Prospect} - {Role}) - Est. ${Ticket}+` (confirmed in the published workflow). Description = AI dossier, Meet link → Google Sheet "Fenebris Master Scheduled Meetings" tab "Scheduled Meetings" (13 requested columns + `Booking ID` match key) → Postgres `meetings` upsert (lead BOOKED, sequence paused) → Smartlead pause of that lead (skipped when the booking is cancelled) → dashboard. Plus `fenebris-meeting-update` (dashboard outcome/notes → Sheet row). A Google Sheets failure no longer blocks the Postgres row or the Smartlead pause (`onError: continueRegularOutput`). The Find-event step only accepts an event that starts within 10 minutes of the booking, so a second booking by the same person never overwrites the first. The calendar id is looked up at run time (`googleCalendarIdNode` + `calExpr` in `n8n/lib.mjs`) because the Google node rejects `"primary"`.

**Booking from the chat (built 2026-10-28, `n8n/wf2-outreach-events.mjs`, helpers in `n8n/helpers.mjs`)**
- Thread memory: `Smartlead: Get Thread` (`GET /campaigns/{cid}/leads/{lid}/message-history`) feeds the whole thread into the draft prompt. Needs real Smartlead ids; a local pretend reply has none, so the thread is empty there.
- Draft rules: answers only from the value proposition, services and `<case_studies>`; never invents a price, client, or number. Output `{subject, body, safe_to_send, accepted_slot_iso}`.
- Offered times: Cal.com open slots minus Google Calendar busy times (freeBusy), 08:00–18:00 prospect-local, up to 3. Each time is a signed button: `PUBLIC_N8N_URL/webhook/fenebris-pick-slot?e=<email>&s=<iso>&k=<sig>` (pure-JS HMAC with `DASHBOARD_WEBHOOK_SECRET`). **With `PUBLIC_N8N_URL` empty the email lists the times as plain text and the person replies with one** (chat acceptance path).
- Click path: verify signature → a scanner or preview only gets a "Confirm this time" page; a real click (`c=1` or `Sec-Fetch-User`) re-checks Calendar busy → `POST /v2/bookings` on Cal.com (header `cal-api-version: 2026-02-25`) → HTML "You are booked" page → 5 s wait → internal POST of a synthetic `BOOKING_CREATED` to `N8N_INTERNAL_URL/webhook/fenebris-cal-booking` (meeting lane writes Calendar event with Meet, Sheet, `meetings`, lead BOOKED, Smartlead pause) → in-thread confirmation "Your slot is booked for …" (only when Smartlead ids exist) → stored as `AI_REPLY_SENT` with sentiment `Slot_Booked`.
- Chat path: the model sets `accepted_slot_iso` only on a clear acceptance of one specific time; it must be in the open-slot list and classifier confidence ≥ 0.6, else ignored. The first "I am interested" never books. A time that is not open (e.g. 11:00 when only 10:00 is free) is declined politely and the real times are offered again.
- Config keys: `PUBLIC_N8N_URL` (public base for buttons; empty now), `N8N_INTERNAL_URL` (`http://localhost:5678`), `SMARTLEAD_CAMPAIGN_ID` (fallback `4238486`).

## 11. Production hosting design (deployed 2026-10-29)
- One VPS, `/opt/fenebris`: Postgres 16 (databases `fenebris` + `n8n`), n8n 2.40.5, dashboard, Caddy (auto HTTPS), backup container (daily `pg_dump` of both DBs, 14 days kept in `/opt/fenebris/backups`). Only Caddy publishes ports (80/443). Domains `APP_DOMAIN` (dashboard, basic auth) and `N8N_DOMAIN` (n8n) come from `.env`.
- Inside compose the baked config is: `DASHBOARD_URL=http://dashboard:3400`, `N8N_INTERNAL_URL=http://localhost:5678`, `PUBLIC_N8N_URL=https://<N8N_DOMAIN>`, Postgres credential host `db`. `DASHBOARD_WEBHOOK_SECRET` = server `WEBHOOK_SECRET` (new strong value, not the local one).
- Flow: `npm run deploy:init -- --app app.<domain> --n8n n8n.<domain> --host <ip>` (writes git-ignored `deploy/.local/*`, keeps secrets on re-run) → `npm run deploy -- --setup` (Docker, ufw, fail2ban, swap, key-only SSH) → `npm run deploy -- --init` (uploads `.env` + `n8n-config.json`) → `npm run deploy` (uploads `git archive HEAD`, then `deploy/remote-deploy.sh`: build image, `prisma db push` (refuses destructive changes), compose up, import credentials, build + import + publish the workflow, restart n8n, smoke test).
- GitHub Actions `.github/workflows/deploy.yml`: on push to `main` runs tsc, lint, helper tests, n8n build check, then `scripts/deploy.mjs`. Secrets the user adds once: `DEPLOY_HOST`, `DEPLOY_SSH_KEY` (a dedicated key, not the personal one), `DEPLOY_KNOWN_HOSTS` (`ssh-keyscan -t ed25519 <ip>`).
- The workflow is built on the **server** from its own `n8n-config.json` (API keys never go to GitHub). Google credentials `y5FL0LJTf7OK7BZo` (Calendar) and `dXHwZhsv0bI9TBiw` (Sheets) are created once as EMPTY placeholders with those same ids; a human opens each in the n8n UI, enters the Google OAuth client id/secret and clicks Sign in.
